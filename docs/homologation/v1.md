# Aceite final v1 (S14)

Este documento fecha a execução sequencial de S01 a S14 descrita na seção
20 do PRD. Não substitui o aceite formal do produto (seção final) — reúne
o que foi implementado e verificado, para que esse aceite tenha uma base
concreta.

## Rastreabilidade (seção 22 do PRD)

Toda linha das matrizes 22.1 e 22.2 aponta para tarefas `Sxx-Txx`
concluídas nesta execução (ver checkboxes marcados em cada seção 20 do
PRD e o histórico de commits "Sprint 1" a "Sprint 13" mais este fechamento
de S14). Nenhum requisito RF-01 a RF-12 ou RT-01 a RT-10 foi removido do
escopo por adiamento silencioso — onde uma tarefa não pôde ser
completamente exercitada (ver "Pendências externas" abaixo), o gate H-xx
correspondente permanece com a lacuna explicitamente documentada no
respectivo `docs/homologation/*.md`, nunca marcado como satisfeito sem
ressalva.

## O que foi genuinely verificado nesta execução

Cada sprint (S01–S14) tem seu próprio `docs/homologation/*.md` com
evidência de execução real — scripts contra a pilha Docker local rodando
de verdade (não apenas leitura de código), `django.test.Client`/
`AsyncClient` contra views reais, e, a partir de S14, navegação real via
Chrome/CDP (`agent-browser`) percorrendo login → escolha de organização →
painel. Bugs reais encontrados e corrigidos ao longo do caminho (lista
não exaustiva, cada um com evidência no documento da sprint em que
apareceu):

- S04: extensão `btree_gist` ausente da migration de agenda; tópico de
  outbox duplicado para lembretes de 24h/2h.
- S06: base de definições do ClamAV nunca apontava para o volume
  persistente `/data/clamav`.
- S10: três bugs em `prepare_recovery` (campo binário em `TextField`,
  status de entrega ausente do `choices`, lookup de `AIJob` quebrando o
  comando inteiro antes de S11 existir).
- S11: dispatcher de outbox só suportava um consumidor por tópico —
  quebraria silenciosamente o handler financeiro ao registrar o de IA.
- S14: ausência de qualquer tela para escolher organização após login
  (login sempre redirecionava para uma URL sem view), e perda do destino
  original em links diretos antes da escolha de organização.

## Liberação de funcionalidades elegíveis

Elegível para uso com dados sintéticos/piloto interno **sem** as
pendências acima: toda a jornada assistencial e administrativa (cadastro,
agenda, prontuário, anexos, documentos assinados com certificado próprio
do médico quando P-05 resolver tecnicamente o mesmo mecanismo, CRM,
financeiro, relatórios, chat/IA com política de privacidade fail-closed).

**Não elegível** para uso com dado real de paciente até resolução das
pendências relevantes: envio de IA a provedor externo com dado
identificado (P-06/P-09), emissão de documento com certificado ICP-Brasil
real (P-05), operação fora de um ambiente com backup externo verificado
(P-10), captura via scanner real (P-08), e qualquer publicação em VPS real
(P-02).
